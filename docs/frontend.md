# Capibara Analytics — запуск и подключение

Текущий статус задач участника 4 и список имеющихся/недостающих данных: [frontend-status.md](frontend-status.md).

Реализованы четыре страницы: **Обзор**, **Заказы**, **Проверки**, **Модель**. Аккаунтов нет. Мобильные страницы прокручиваются вертикально, нижняя навигация закреплена. Навигация использует hash-маршруты; прямую ссылку на карточку заказа можно открыть после обновления страницы.

## Быстрый запуск

Нужен Node.js 22+ и npm. Из корня репозитория:

```bash
cd web
npm install
npm run dev
```

Открыть **http://localhost:5173/#/overview**. Одна команда запускает Vite и API на порту 3001. По умолчанию (`DATA_SOURCE=team-snapshot`) дашборд показывает **переданные пользователем SQL-результаты команды**, сохранённые в `web/server/team-snapshot.mjs`: все 24 месяца, топ-10 продавцов, чек и средние строки/единицы, покупателей и повторные покупки. Сумма месяцев проверяется как 13 221 498,11; доставленных заказов 96 478. Это статичный снимок, а не онлайн-БД. Фильтры, заказы и проверки недоступны для SQL-снимка: он не содержит подробных записей. Страница «Модель» доступна без базы, без счётчиков строк. Десять категорий с видимыми полными названиями показаны отдельно, остальные 64 — одной явно подписанной суммарной группой; полный список 74 категорий по неполным скриншотам не выдумывался. Подробные страницы доступны в demo/core; текущий приоритет — правильный Обзор.

Для интерфейсных экспериментов можно явно выбрать `DATA_SOURCE=demo`. Это синтетические заказы, не данные команды. Для полноценной интерактивности выбрать `DATA_SOURCE=core` и доступное подключение. При ошибке core никакой автоматической подмены источника нет.

Для телефона в той же Wi-Fi сети: открыть `http://IP-КОМПЬЮТЕРА:5173`. На компьютере должен быть доступен порт 5173. Vite пересылает `/api` на локальный сервер, поэтому телефон не подключается к `localhost:3001`. Не публикуйте сервер разработки в интернет.

## Сборка и запуск одной службы

Эти команды и команды проверки ниже выполняются из каталога `web/`.

```bash
npm run build
npm start
```

Открыть **http://localhost:3001**. Express раздаёт собранный фронтенд и `/api` с одного адреса. Для доступа с телефона использовать IP компьютера и порт 3001. Внешнее размещение потребует HTTPS и, при появлении рабочих данных, контроля доступа.

## Подключение модели команды

В каталоге `web/` скопировать `.env.example` в `.env`, установить:

```dotenv
DATA_SOURCE=core
DATABASE_URL=postgresql://hack:hack@localhost:5432/marketplace
PORT=3001
```

Перезапустить сервер. `core` должна быть создана инженером данных. Приложение не запускает загрузку, не создаёт таблицы и не меняет `raw`. Подключение не является выполнением обязательных SQL-ответов команды.

Контракт адаптера: `docs/core_model.md` из `origin/feature/core-model`, коммит `4bc3b28`; сверено с DDL загрузчика из `origin/model/load.sql`, коммит `f3d967d`. Используемые панелью поля совместимы с новой моделью. Адаптер читает:

- `core.orders`: `order_id`, `customer_id`, `order_status`, `order_purchase_at`.
- `core.customers`: `customer_id`, `customer_unique_id`, `state`.
- `core.order_items`: `order_id`, `product_id`, `seller_id`, `price`, `freight_value`.
- `core.products`: `product_id`, `category_name`.
- `core.categories`: `category_name`, `category_name_english`.
- `core.sellers`: `seller_id`, `city`, `state`.

Имена при необходимости меняются только в `server/core.mjs`. Чтение происходит в согласованном снимке `REPEATABLE READ READ ONLY`; SQL ограничен тайм-аутом. Цены переводятся в целые сентаво. Данные кешируются на 60 секунд, дальнейшие агрегаты считаются сервером в памяти, браузер получает только итоговые таблицы. Для текущего объёма Olist это простой адаптер; при росте перенесите группировки в SQL-витрины и кешируйте их по параметрам. Платежи не присоединяются к позициям. Ошибка чтения `core` возвращает 503, без автоматического перехода на demo.

В ветке `origin/model/load.sql` появились загрузчик и `reports/core_acceptance.md` с 23 успешными проверками у инженера данных. CSV и подробные JSON-снимки в Git не хранятся. На текущем компьютере подключение к `localhost:5432` проверено: другая локальная PostgreSQL отклоняет пользователя `hack` по правилу Ident; контейнер `hack_postgres` не запущен. Чужие настройки PostgreSQL не менялись. Поэтому онлайн-чтение core пока не включено; по умолчанию показан отдельно подписанный SQL-снимок команды. Порт 5433 со скриншотов также проверен: на этом компьютере соединение отклонено. Для перехода на реальные данные нужен доступный адрес заполненной базы `core` в `DATABASE_URL` (при занятом 5432 можно согласовать другой порт для базы команды). После подключения сверить результаты с SQL аналитика. Отчёт о проверках сам по себе не является помесячной выгрузкой для панели.

## API

`GET /api/health` — состояние процесса и настроенный режим, **не проверка доступности БД**.

`GET /api/overview?start=2016-09&end=2018-08&state=all`

- `start`, `end` — включительные календарные месяцы оформления, диапазон 2016-09…2018-08.
- `state` — штат **покупателя** либо `all`; список доступных штатов приходит в `regions`.
- Ответ: `meta`, `kpis`, `monthly`, `sellers` (10 лидеров), `categories` (все), `regions`.
- Все денежные поля с суффиксом `Cents` — целые сентаво; делить на 100 для BRL.
- Неопределённые средние и доли — `null`. Нули календарного ряда — `0`.
- 400 — некорректные фильтры, 503 — источник недоступен.

## Проверка

### Дополнительные страницы и API

- `#/orders` — поиск по ID, фильтры периода/региона/статуса, сортировка, серверная пагинация по 20 заказов. На телефоне — карточки. `#/orders?id=...` открывает подробности независимо от текущего среза списка.
- `GET /api/orders` принимает фильтры обзора и `q`, `status`, `sort=date_desc|date_asc|amount_desc`, `page`, `pageSize` (1–100). Детали не передаются со всем списком.
- `GET /api/orders/:id` — позиции, отдельные платежи, отзывы и доступные даты. Отсутствующий платёж — `null`, а не 0. Идентификатор товара используется вместо выдуманного названия. Сумма оплаты не умножается на рассрочку.
- `#/quality`, `GET /api/quality` — вычисляемые проверки **всего снимка**, без фильтров периода/региона. Статусы: пройдено, наблюдение, ошибка, не выполнялась. Примеры открываются в заказах. Сверка raw/core не выполняется этим API и явно отмечена отдельно.
- `#/model`, `GET /api/model` — контракт команды, 8 сущностей, гранулярность, поля, PK/FK, связи. Поиск, масштаб и горизонтальная прокрутка схемы. Счётчики отражают текущий источник (в demo — только демонабор). При недоступной БД сама документированная схема остаётся доступной, счётчики — неизвестны.
- Режим core дополнительно читает `order_approved_at`, `delivered_carrier_at`, `delivered_customer_at`, `estimated_delivery_date`, `shipping_limit_at`, `order_payments`, `order_reviews` с `review_created_at` по контракту `4bc3b28`. Данные читаются отдельными запросами в одном снимке и собираются по order_id без размножения сумм.
- Демообогащение датами/платежами/отзывами не меняет цены и KPI исходного демогенератора. Есть примеры раздельной оплаты, пропущенных дат и денежных расхождений.

### Команды

```bash
npm test
npm run build
```

Проверяются уровни расчёта, учёт доставки/статусов, несколько одинаковых единиц и несколько продавцов, повторный покупатель, неизвестная категория, пустой месяц, сверка агрегатов, валидация API и отсутствие подмены источника при ошибке.

## Файлы

Типографика: название и заголовки — локальный Bounded. Весь остальной текст — локальный вариативный Geologica с включённой осью `CRSV=1` (Cursive), без искусственного наклона. Источник: [Google Fonts / Geologica](https://github.com/googlefonts/geologica); лицензии шрифтов в `web/public/fonts/`. Денежные значения показываются без повторяющегося символа R$; общая подпись указывает бразильский реал (BRL), пересчёта в другую валюту нет.

Приложение целиком находится в `web/`. Упоминаемые выше `server/core.mjs` и `.env` — пути относительно `web/`.

`web/src/` — React + TypeScript, Tailwind/CSS, Recharts, Lucide и локально поставляемая Geologica. `web/server/` — Express, демогенератор, расчёты и адаптер PostgreSQL. Конфиденциальные параметры только в `web/.env`, не в клиентском коде.

## Подключение mart

В participant3/analysis добавлен DATA_SOURCE=mart: backend агрегирует SQL из mart и сохраняет JSON-контракт /api/overview, графики и фильтры. Инструкция и права доступа — docs/analytics/mart.md. Пример конфигурации — web/.env.example. В режиме mart страницы заказов и качества читают core на backend с кэшем на минуту; модель показывает все три слоя. Пароли передаются только backend через игнорируемый web/.env.
