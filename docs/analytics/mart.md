# Контракт витрин

Установка: `psql ... -v ON_ERROR_STOP=1 -f model/03_mart.sql`, после успешного построения core. Повторный запуск безопасен при неизменном контракте. `raw` и `core` не изменяются. Проверка: `psql ... -f checks/mart.sql`.

Это обычные VIEW в PostgreSQL 16: читают текущий core без отдельного обновления. Витрины дают единые формулы, но пока не сохраняют агрегаты и не обещают ускорения. При измеренной необходимости переводим тяжёлые агрегации в материализованные представления с расписанием обновления.

| Объект | Одна строка | Условия |
|---|---|---|
| order_metrics | Заказ | Все статусы, пустой заказ сохраняется; has_items отличает отсутствие позиций от нулевой суммы |
| delivered_items | Единица товара: order_id + order_item_id | Только delivered |
| monthly_sales | Месяц покупки | Delivered с позициями; календарь минимум сентябрь 2016 — август 2018, расширяется по данным |
| seller_monthly_sales | Продавец за месяц | Delivered, выручка только по его товарам |
| category_monthly_sales | Код категории за месяц | Delivered, NULL-категория сохранена |
| customer_purchases | Устойчивый customer_unique_id | Все статусы за всё время |
| repeat_customers | Общий итог покупателей | Два и более заказа, все статусы, за всё время |
| sales_kpis | Общий итог продаж | Delivered с позициями за всё время |

Выручка = SUM(price), без доставки. Чек = SUM(price + freight_value) на заказ. Единицы = число записей order_items, строки = уникальные (product_id, seller_id) внутри заказа. Деньги — numeric, округление только на выводе. Пустой месяц: нулевые заказы и выручка, средний чек NULL (чека не было).

Категории группируются по исходному коду: одинаковые отображаемые названия не склеивают разные категории. Название: перевод → исходный код → «Не указана».

## Правила дашборда

- Выручку, единицы и заказы внутри одного продавца можно суммировать по месяцам.
- Заказы разных продавцов/категорий складывать в общий итог нельзя: один заказ может присутствовать в нескольких группах.
- Средний чек за период = SUM(order_value) / SUM(orders) из monthly_sales, а не AVG месячных средних.
- Доли категорий считать после применения фильтра, от суммы выручки в выбранном срезе.
- Повторные покупатели и sales_kpis сейчас за всё время. Не изображать их как зависящие от фильтра месяца. Для периодных повторных покупок сначала согласовать определение (когорта или повтор внутри периода).
- Не соединять позиции напрямую с платежами и отзывами: сначала агрегировать каждую связь до заказа.
- dashboard_reader читает только 5 агрегированных витрин; подробные заказы/идентификаторы покупателей ему не выдаются.
