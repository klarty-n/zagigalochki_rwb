## Как подключатся остальные данные

1. Участник данных предоставляет адрес и доступ к **заполненной core**, совместимой с контрактом команды. Передача Git-ветки с SQL не передаёт саму базу.
2. В `web/.env` задаются `DATA_SOURCE=core` и `DATABASE_URL=postgresql://.../marketplace`, затем перезапускается API.
3. Сервер читает orders, customers, items, products, sellers, categories, payments и reviews в согласованной транзакции **только для чтения**. raw не используется и не изменяется.
4. Браузер получает данные через `/api/overview`, `/api/orders`, `/api/orders/:id`, `/api/quality`, `/api/model`. Фильтры и подробные разделы становятся доступны в режиме core.
5. Обновить страницу или нажать кнопку обновления; снимок core кешируется на 60 секунд. Это обновление по запросу, а не непрерывная подписка на изменения.
6. Сверить пять SQL-результатов с аналитиком и отдельно проверить области расчёта покупателей и продаж. В core покупатели панели считаются в выбранном срезе; контроль 96 096 относится ко всей выгрузке.

Если команда передаст только выгрузки результатов, можно обновить сохранённый SQL-снимок, но подробные заказы и произвольные фильтры из итогов автоматически не появятся. Универсального импорта CSV/JSON через интерфейс сейчас нет.
