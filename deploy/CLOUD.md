# Общая база и общий дашборд

## Уже размещено

Neon Free: проект DATABASE, PostgreSQL 16, AWS Frankfurt, база marketplace.
Исходные raw/core и восемь mart-витрин перенесены с локального Docker в облако. Сверка 16 таблиц, трёх денежных сумм и месячной выручки сохранена в reports/cloud-migration.md.

База больше не зависит от ноутбука владельца. Локальный Docker остаётся средой разработки и резервной исходной копией. После переключения не загружать старый локальный дамп поверх общей базы: изменения модели и новые загрузки применяются централизованно.

## Участники команды

Для работы с SQL нужен только клиент DBeaver и реквизиты общей базы, а не локальные PostgreSQL, Docker, CSV и загрузчик. Отдельный team_reader имеет только чтение восьми таблиц core и витрин mart. Администратор передаёт его подключение команде вне GitHub; файл deploy/secrets/neon-team-reader.url содержит секрет и не коммитится.

Хост и база указаны в отчёте миграции; порт 5432; SSL обязателен. Пароль не публикуется в README. Для frontend-разработки используется отдельный dashboard_backend, для миграций — владелец Neon. Эти учётки не взаимозаменяемы.

## Сайт и API

Рабочий адрес: https://capibara-marketplace.onrender.com. Сервис создан на Render Free и проверен внешними HTTP-запросами. Подтверждение почты Render завершено. Реквизиты для команды находятся в локальном игнорируемом deploy/secrets/team-access.txt; это файл с паролями, его передают только участникам, не коммитят.


render.yaml описывает один Render Web Service на Free, собирающий web из participant3/analysis. Он отдаёт и React, и /api: браузеру не нужны реквизиты БД. В Render DATABASE_URL задаётся секретом из neon-backend.url. HOST=0.0.0.0, PORT задаёт Render. Node 22, сборка npm ci && npm run build, запуск npm start.

DASHBOARD_USERNAME=team и DASHBOARD_PASSWORD ограничивают доступ к сайту общей командной учёткой (HTTP Basic поверх HTTPS). Пароль не связан с паролем БД. /api/health доступен хостингу без авторизации. В локальной среде пароль интерфейса необязателен; в render.yaml он генерируется.

Бесплатный Render может засыпать после простоя, первый запрос будет медленнее. Бесплатные ресурсы имеют квоты: это демонстрационное облачное размещение, не гарантия постоянной производственной доступности. PostgreSQL хранится в Neon, а не во временной файловой системе Render. Не создавать отдельный Render Free Postgres: он имеет ограниченный срок жизни.

## Производительность и развитие

SQL-обзор агрегируется в mart на стороне БД; пул ограничен тремя соединениями. Детализация пока использует core-провайдер в памяти backend: облачный кэш 10 минут уменьшает повторную передачу всего набора, локальный по умолчанию 1 минута. Данные карточек содержат фактическую дату снимка. При росте заменить этот провайдер SQL-пагинацией и адресными запросами; далее индексы/предагрегации по измеренным задержкам. Масштабирование CPU и памяти выполняется в хостинге и Neon в пределах выбранного плана; платные изменения только по отдельному решению команды.

## Инструменты переноса

- deploy/migrate_neon.py: копирует из hack_postgres в ПУСТУЮ Neon, использует pg_dump/pg_restore 16 внутри контейнера, проверяет TLS и отказывается перезаписывать существующую цель. Копирование происходит один раз, не при старте сайта.
- deploy/cloud_psql.py --file ПУТЬ: запуск SQL на общей базе владельцем; требует локальный Docker только на машине администратора и игнорируемый файл neon-owner.url. Остальным этот инструмент не нужен.
- deploy/secrets/ и deploy/backups/ исключены из Git. Резервные копии хранить дополнительно вне ноутбука и проверять восстановление; бесплатная история Neon не заменяет резервную стратегию.

Официальные ограничения: https://neon.com/blog/neon-free-plan-1-gb-per-project и https://render.com/docs/free.
